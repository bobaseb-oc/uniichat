# Lessons

- 2026-10-20: I told the user agent shells inherit the server's environment. They don't: `shell`/`read`/`write`/`edit` run on the device (Term.ts, Machine.ts), so they get the terminal's environment. Rule: before claiming what a tool's process can see, find which process runs it (Tools.ts header: device tools vs server tools).
- 2026-11-11: A mutation check "passed" (each mutant failed a test) while the file didn't even parse, so every run failed for that reason. Rule: a mutation check counts only if the unmutated file passes first and each mutant shows "N-1 pass, 1 fail", not just "fail".
- 2026-11-12: A new Cloud test hard-coded "http://127.0.0.1" as SITE; it passed alone and failed in the full suite, where another file loads Config first with its own UNII_SITE. Rule: tests compare against config.SITE (imported), never a literal site, since every test file shares one process and one Config.
- 2026-11-12: Unit tests passed for the Crew view, but the real page opened `/?demo=1#crew` in Chat mode: boot() rewrote the URL to "/" and dropped the hash. Only an end-to-end run (headless Chrome over CDP against a throwaway server) showed it. Also, headless Chrome draws requestAnimationFrame only for a frame: take a screenshot before reading the DOM, or the reads are a paint behind. Rule: a web change that touches routing or start-up gets one end-to-end run, not only unit tests.
- 2026-11-12: A tsc "before" count of 0 came from stashing away a new file the command named, so tsc never ran. Rule: a before/after comparison counts only if both runs show some output (print the per-file counts), and the "before" run names only files that exist at HEAD.
- 2026-11-12: Flags kept in a variable (`O="--noEmit …"; tsc $O`) reach tsc as ONE argument in zsh (no word splitting), so tsc only printed "Unknown compiler option" and both counts were 0. Rule: type flags inline or use an array/function; and check the raw output's line count before trusting a diff.
- 2026-11-12: The user couldn't get back to Chat from Crew. The switch worked; Chat mode was buried under the footer's old crew list (one row per agent), taller than the window, covering the chat and header. My end-to-end runs had no crew, so they missed it. Rule: check web layouts with the demo crew (/?demo=1), in every mode, by real clicks (CDP Input events, with elementFromPoint at the click), not only with an empty account.
- 2026-11-12: The Chat fix wasn't the whole bug: the user still stayed on #crew (no agents). The paint wrote the Crew's hash back whenever it differed, so a paint landing between a click's new hash and its hashchange undid the click. My click tests passed because no server message landed in that gap. Rule: the URL is the one source of a mode: paint reads it, only acts write it; test the gap by changing the URL with no event, painting, then sending the event.
- 2026-11-12: Bun ran a namespace with two `export async function answer` (the later silently replaced the socket handler), and an act with its own `id` field that `link_send`'s `{ id, ...msg }` would overwrite; the tests passed, only tsc (TS2393, TS2322) caught both. Rule: before naming a new Chat/Tools function, grep `function <name>` in the file; never give an act a field named `id`; read tsc's non-environment errors for every change, not just the counts.
- 2026-11-12: A new `const SUMMARIES = 50` inside the Chat namespace shadowed the imported SUMMARIES wait ("summaries"), so Chat.waits would have returned 50 and the "compressing earlier messages" banner would have broken; 306 tests passed, only tsc's TS2322 showed it. Rule: before naming any constant or function inside a namespace, grep the file's imports and the namespace for that name (the 2026-11-12 function-name rule covers constants too), and read every non-environment tsc error.

## 2026-11-13: "address all" means close everything closable
Pattern: I shipped PR #8 with five items "left open, by design", and the user asked why they weren't closed.
Rule: when asked to address all points, every item I can fix is fixed before the PR; an item stays open only
when it needs the user's call, and then I ask (with a recommendation) before opening the PR, not after.
Also: an unsandboxed shell has a different $TMPDIR than a sandboxed one, so mutation backups belong in the
repo (work-tasks/), never in $TMPDIR across sandbox modes.
